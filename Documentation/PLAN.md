# План: Aircraft 0.4

> **Статус:** сделано в ветке `aircraft-0.4`. Отличия от плана: Readability.js и markdown-it не подключались. Извлечение статьи и рендер Markdown написаны свои, без сторонних библиотек. Уведомления сайтов не сделаны: у WKWebView на macOS нет для них публичного API, сайтам отвечаем «запрещено».

Что входит, по пунктам из обсуждения:

- **Базовые вещи** — всё, кроме аварийного окна без истории. Вместо него делаем режим инкогнито.
- **Из Arc** — профили, папки вкладок с вложенными папками (с лимитом глубины), автоархив. Вместо дерева вкладок — группы: ссылка, открытая в новой вкладке, попадает в группу.
- **Из Safari** — всё, кроме перевода страницы.
- **Новое** — просмотрщик PDF и Markdown.

Peek, Little Arc, счётчики непрочитанного, веб-панели, командная строка и ИИ в этот план не входят.

## Что уже сделано

- **Вырезание `utm_*`, `fbclid`, `gclid`** работает при включённом блокировщике трекеров (`AdBlocker.cleanedURL`). Осталось применять его и при копировании ссылки (⌘⇧C).
- **«Скрыть отвлекающее»** уже есть: пипетка `ElementPicker` (⌥⌘B) сохраняет правило `сайт##селектор`. Можно добавить список скрытых элементов для сайта со сбросом, но это необязательно.

## Решения по умолчанию

Это нужно подтвердить. Если не скажешь иначе, делаю так:

1. **Инкогнито: ⌘⇧P**, а ⌘⇧N остаётся новым окном. Альтернатива — как в Safari и Chrome: ⌘⇧N инкогнито, ⌥⌘N новое окно.
2. **Профиль переключается внутри окна**, как в Arc: переключатель внизу панели вкладок, ⌃1…⌃9. У разных окон могут быть разные профили.
3. **Лимит вложенности папок: 3 уровня** (папка → подпапка → подподпапка). Это константа, поменять легко.
4. **Закладки — отдельное хранилище** (⌘D, панель, Spotlight, импорт). Закреплённые вкладки и папки в панели живут отдельно, как сейчас. Если сваливать сотни импортированных закладок в панель вкладок, она станет нечитаемой.
5. **Подсказки поисковика в Spotlight включены**, источник — выбранный поисковик. Отключаются в настройках.
6. **Автоархив по умолчанию: 24 часа**, только для незакреплённых вкладок вне папок.

## Новые сочетания клавиш

Все проверяются по физической клавише (`keyCode`), как сейчас ⌘T, чтобы работать в русской раскладке.

| Сочетание | Действие |
|---|---|
| ⌘F, ⌘G / ⌘⇧G, Esc | Поиск на странице, следующее / предыдущее, закрыть |
| ⌥← / ⌥→ | Предыдущая / следующая вкладка (по кругу) |
| ⌘⇧T | Вернуть закрытую вкладку |
| ⌘= / ⌘− / ⌘0 | Масштаб страницы |
| ⌘⇧C | Скопировать URL (без трекинговых меток) |
| ⌘⇧M | Отключить или включить звук вкладки |
| ⌘D | Добавить в закладки |
| ⌘⇧B | Панель закладок |
| ⌘Y | История |
| ⌘⇧P | Окно инкогнито |
| ⌃1…⌃9 | Переключить профиль |
| ⌘O | Открыть файл (PDF, Markdown, HTML) |

## Этап 0. Фундамент

Без этого остальные этапы будут переписывать одно и то же.

**Хранилище на диске.** `~/Library/Application Support/Aircraft/` вместо UserDefaults для всего, что растёт: `Profiles/<id>/session.json`, `history.sqlite`, `bookmarks.json`, `sites.json` (масштаб и разрешения для сайтов). Для SQLite достаточно системного `import SQLite3` и тонкой обёртки, без зависимостей.

**Сессия по окнам.** Сейчас все окна пишут в один ключ `browserSessionV1` и затирают друг друга. Сессия станет списком окон, каждое со своим `windowID`, и при запуске восстановятся все окна. Миграция: старая сессия превращается в первое окно профиля по умолчанию.

**`TabModel` получает поля:**
- `lastActiveAt` — нужно для автоархива;
- `content: .web | .pdf(URL) | .markdown(URL)` — для просмотрщиков;
- `interactionState: Data?` — история «назад/вперёд», `WKWebView.interactionState` (публичный API).

Сохранять `interactionState` нужно и при усыплении вкладки. Сейчас после пробуждения у вкладки теряется история переходов.

**Перетаскивание вкладок.** Сейчас вкладки нельзя переставлять мышью, а для папок и групп это обязательно. Нужно в боковой панели, в верхней полосе и в узкой (`MobileSidebarView`).

## Этап 1. Быстрые вещи

| Задача | Как |
|---|---|
| ⌘F | Плашка поиска сверху страницы. `WKWebView.find(_:configuration:)` подсвечивает и прокручивает; число совпадений («3 из 17») считаем JS-скриптом в изолированном мире `.defaultClient`. Esc или переход на другую страницу закрывают плашку |
| ⌥← / ⌥→ | Переключение на предыдущую и следующую вкладку по кругу, в порядке отображения (после этапа 6 — по дереву, пропуская свёрнутые папки и группы). Конфликт: в полях ввода ⌥← / ⌥→ двигает курсор по словам, и это ломать нельзя. Поэтому сочетание перехватывается, только если фокус не в редактируемом поле. В Spotlight и полях AppKit это видно по first responder (`NSTextView`). Для страницы — маленький скрипт в изолированном мире: по `focusin` / `focusout` он сообщает приложению, стоит ли фокус в `input`, `textarea` или `contenteditable`, и монитор клавиш читает этот флаг. Если фокус в поле, событие уходит странице как обычно |
| ⌘⇧T | Стек закрытых вкладок на окно, до 25 штук: URL, заголовок, `interactionState`, место в панели (родительская папка или группа и индекс). Пункт меню «Недавно закрытые». Вкладка возвращается на прежнее место с историей переходов |
| Масштаб | Словарь «хост → масштаб» в `sites.json` профиля. Убрать сброс `pageZoom = 1` в `configureContentMode`, применять масштаб на `didCommit`. При изменении на секунду показывается значок «110 %» |
| ⌘⇧C | Копирует URL активной вкладки через `AdBlocker.cleanedURL` и показывает уведомление «Ссылка скопирована» |
| Звук | Значок динамика на вкладке, если она играет звук (KVO по приватному `_isPlayingAudio` с проверкой `responds(to:)`). Клик по значку или ⌘⇧M отключает звук (`_setPageMuted:`). В контекстном меню — «Выключить звук остальных вкладок». Вкладки со звуком не усыплять |

## Этап 2. История, подсказки, закладки

**История** — `history.sqlite` профиля.
- Таблица `visits` (url, title, host, visited_at, transition) и полнотекстовый индекс FTS5 по заголовку и URL.
- Запись при `didFinish` основного фрейма; заголовок обновляется при его изменении.
- В инкогнито не пишется ничего.
- Окно истории по ⌘Y: поиск, группировка по дням, удаление записи, сайта или периода («за последний час», «за сегодня», «всё»).
- История из мода `aircraft-tab-history-accounts` больше не нужна. В моде остаётся только список аккаунтов; в описании мода пометить, что историю ведёт браузер.

**Подсказки в Spotlight.** Секции в таком порядке: открытые вкладки, закладки, история, подсказки поисковика.
- Ранжирование по частоте и давности посещений (frecency).
- Автодополнение домена прямо в поле: набрал «git» → «github.com».
- Сетевые подсказки запрашиваются с задержкой ~150 мс, старые запросы отменяются.
- Источники: DuckDuckGo `ac/`, Google `complete/search?client=firefox`, Яндекс `suggest-ya.cgi`.
- Существующие подсказки префиксов (`URLSystemSuggestions`) остаются отдельной секцией.

**Закладки.**
- Дерево папок в `bookmarks.json`, лимит вложенности тот же — 3 уровня.
- ⌘D открывает всплывающее окно: название и папка.
- Панель ⌘⇧B со списком и поиском, перетаскиванием и переименованием.
- Звёздочка в Spotlight и верхней полосе, если страница уже в закладках.

**Импорт** (Настройки → Браузер → Импорт):
- Chrome: `~/Library/Application Support/Google/Chrome/<профиль>/Bookmarks` (JSON) и `History` (SQLite; пока Chrome запущен, файл заблокирован, поэтому сначала копируем во временный файл). Так же для Arc, Brave и Edge — у них такой же формат.
- Safari: `~/Library/Safari/Bookmarks.plist` и `History.db`. Нужен полный доступ к диску. Если доступа нет, показываем инструкцию и кнопку открытия нужного раздела Системных настроек.
- Запасной вариант без прав: HTML-файл закладок (формат Netscape), который экспортирует любой браузер.

## Этап 3. Разрешения сайтов и PiP

**Камера и микрофон.**
- `webView(_:requestMediaCapturePermissionFor:initiatedByFrame:type:decisionHandler:)` показывает плашку над страницей: «Разрешить», «Запретить», «Только сейчас».
- Решение сохраняется в `sites.json` профиля.
- Пока идёт запись (`cameraCaptureState` / `microphoneCaptureState`, KVO), на вкладке горит красная точка, по клику запись останавливается.
- Нужно добавить в Info.plist `NSCameraUsageDescription` и `NSMicrophoneUsageDescription`.

**Геолокация.** Через приватный делегат WebKit `_webView:requestGeolocationPermissionForFrame:decisionHandler:` и `NSLocationUsageDescription`. Сначала проверить на прототипе, работает ли это без подписи от Apple.

**Уведомления сайтов.** Публичного API для WKWebView на macOS нет. Делаем короткое исследование (полдня); если не получится — откладываем и отвечаем сайтам «запрещено».

**Настройки сайтов.** Экран в настройках: список сайтов с решениями и масштабом, сброс по одному и всех.

**Картинка в картинке.**
- Команда в контекстном меню вкладки и кнопка поверх видео при наведении.
- JS находит самое крупное играющее `<video>` и вызывает `webkitSetPresentationMode('picture-in-picture')`.
- Риск: WebKit может требовать жест пользователя. Если вызов из приложения не засчитывается как жест — использовать приватный `evaluateJavaScript` с флагом жеста.
- Авто-PiP при уходе с вкладки с видео — настройка, по умолчанию выключена.
- Вкладку в PiP не усыплять и не архивировать.

## Этап 4. Инкогнито

- Отдельное окно с `WKWebsiteDataStore.nonPersistent()`. Хранилище своё у каждого окна, как в Safari: два окна инкогнито не видят cookie друг друга.
- Ничего не пишется на диск: ни сессия, ни история, ни стек закрытых вкладок, ни масштаб, ни решения о разрешениях. Масштаб и закладки читаются из текущего профиля, но не сохраняются.
- Тёмная панель вкладок и значок маски, чтобы окно не перепутать.
- Окна инкогнито не видны агентам по MCP. Нужна отдельная галочка в Настройки → Агенты, по умолчанию выключена.
- Загрузки сохраняются как обычно, но не попадают в списки.
- Блокировщики работают, моды подключаются.

## Этап 5. Профили

- `Profile { id, name, color, symbol }` в `profiles.json`. Каждый профиль — папка `Profiles/<id>/` со своей сессией, историей, закладками и настройками сайтов.
- Cookie и данные сайтов: `WKWebsiteDataStore(forIdentifier: profile.id)` (macOS 14+, у нас минимум 15).
- Профиль по умолчанию остаётся на `WKWebsiteDataStore.default()`, чтобы после обновления никого не разлогинило.
- `TabManager` получает профиль и создаёт все WebView из его хранилища, включая всплывающие окна (`createPopupTab` уже получает конфигурацию от родителя, это работает само).
- Переключатель внизу панели вкладок: кружки с цветом профиля, ⌃1…⌃9, свайп двумя пальцами по панели.
- При переключении вкладки прежнего профиля усыпляются. Это главный способ держать память под контролем: живой только профиль на экране.
- Цвет профиля подкрашивает панель вкладок.
- Управление в Настройки → Профили: создать, переименовать, цвет, удалить. При удалении вызывается `WKWebsiteDataStore.remove(forIdentifier:)` с подтверждением.
- Настройки браузера (поисковик, блокировщики, моды) пока общие для всех профилей.

## Этап 6. Папки и группы

**Модель.** Вместо плоского порядка `tabs` — дерево:

```swift
enum SidebarNode { case tab(UUID), folder(TabFolder), group(TabGroup) }
struct TabFolder { id, title, isExpanded, children: [SidebarNode] }  // глубина ≤ 3
struct TabGroup  { id, title, color, isExpanded, tabIDs: [UUID] }      // только вкладки, без папок
```

`tabs: [TabModel]` остаётся хранилищем, а дерево задаёт порядок и вложенность. ⌘1…⌘9 и «следующая вкладка» идут по дереву в порядке отображения, пропуская свёрнутые папки.

**Папки** (как в Arc).
- Живут в зоне закреплённых и в обычной зоне.
- Создаются через «Новая папка» или выделение нескольких вкладок (⌘-клик) → «Убрать в папку».
- Переименование на месте, сворачивание, перетаскивание вкладок и папок.
- Лимит вложенности: при перетаскивании на 4-й уровень папка не принимает элемент (подсветка красным), а «Новая папка» внутри папки 3-го уровня неактивна.
- Закрытие папки спрашивает подтверждение, если внутри больше 5 вкладок.

**Группы для открытых ссылок** — замена дереву вкладок.
- Ссылка открывается в новой вкладке (⌘-клик, `target=_blank`, `window.open`):
  - родитель в группе → новая вкладка добавляется в эту же группу после родителя;
  - родитель на верхнем уровне без группы → создаётся группа из родителя и новой вкладки, название — имя сайта, цвет — следующий из палитры;
  - родитель внутри папки → новая вкладка встаёт в ту же папку после родителя, без новой группы. Так группа не добавляет уровень вложенности.
- Окна входа (`window.open` с размерами в `windowFeatures`) групп не создают.
- В группе осталась одна вкладка → группа исчезает.
- Действия: переименовать, сменить цвет, свернуть, «Разгруппировать», «Превратить в папку».
- Настройка «Группировать открытые ссылки», по умолчанию включена. Если выключить — работает как сейчас, вкладка встаёт справа.
- Нынешний словарь `openedFrom` заменяется группами.

**Отображение:**
- боковая панель — дерево с отступами;
- верхняя полоса — папка и группа выглядят как цветная «таблетка», клик раскрывает её вкладки рядом (папка — выпадающим меню);
- узкий режим — как боковая панель.

## Этап 7. Автоархив

- Настройка: выкл / 12 ч / 24 ч / 7 дней / 30 дней (по умолчанию 24 ч).
- Проверка по таймеру раз в 10 минут и при пробуждении Mac.
- Архивируются незакреплённые вкладки вне папок, неактивные дольше срока.
- Не трогаются: активная вкладка, вкладки в сплите, со звуком, PiP или камерой, вкладки в группе с активной вкладкой.
- Архив — тот же формат, что и стек закрытых вкладок (с `interactionState`), до 200 записей на профиль.
- Окно «Архив» с поиском; в Spotlight он отдельной секцией после истории.
- Ступенчато: вкладка усыпляется раньше (как сейчас) и архивируется по сроку.

## Этап 8. Из Safari

**Режим чтения** вместо нынешнего CSS.
- Mozilla Readability.js (Apache 2.0) в `Resources`, запускается в изолированном мире только по нажатию.
- Значок в верхней полосе появляется, если `isProbablyReaderable()` вернул true. Проверку запускать после загрузки страницы и только для активной вкладки.
- Своя вёрстка: шрифт (с засечками / без), размер, ширина колонки, тема (светлая / сепия / тёмная), время чтения. Настройки запоминаются.
- Выход по Esc или повторному нажатию.

**Сайт как приложение** («Добавить в Dock»).
- Новый исполняемый таргет `AircraftWebApp` в Package.swift, по образцу `aircraft-mcp`. Это маленькое окно с WKWebView, без панели вкладок.
- Генератор собирает `~/Applications/Aircraft Apps/<Имя>.app`: копия бинарника, `Info.plist` с уникальным `CFBundleIdentifier`, иконка из `apple-touch-icon` или favicon (→ `.icns`), ad-hoc подпись `codesign -s -`.
- У приложения своя иконка в Dock, свой процесс и свои cookie (отдельный bundle ID → отдельное хранилище WebKit).
- Ссылки на другие сайты открываются в основном Aircraft.
- Список приложений и удаление — в Настройки → Браузер.

**«Скрыть отвлекающее»** — уже есть. Можно добавить меню сайта «Скрытые элементы (N) → Показать все».

## Этап 9. Просмотрщики PDF и Markdown

Общее:
- `TabModel.content` из этапа 0.
- ⌘O «Открыть файл…».
- Перетаскивание файла в окно.
- Регистрация в `CFBundleDocumentTypes` для `.pdf`, `.md`, `.markdown`, `.html`, чтобы работало «Открыть в Aircraft» из Finder.

**PDF.**
- Ответ с типом `application/pdf` (или `.pdf` в URL) через `decidePolicyFor navigationResponse` уходит в `WKDownload` во временную папку. Скачивание идёт через сессию страницы, поэтому PDF за логином тоже открываются.
- Вкладка показывает нативный `PDFView` (PDFKit):
  - миниатюры страниц сбоку;
  - номер страницы и переход к ней;
  - масштаб (⌘=/⌘−, «по ширине», «страница целиком»);
  - поиск по ⌘F через ту же плашку из этапа 1;
  - оглавление из `outlineRoot`;
  - «Сохранить в Загрузки», «Открыть в Просмотре», печать.
- Последняя позиция в документе запоминается.
- Временный файл удаляется при закрытии вкладки. После усыпления PDF скачивается заново.

**Markdown.**
- Файлы `.md` и `.markdown` (локальные и по сети, включая `text/markdown` и `text/plain` с расширением `.md`) рендерятся в WebView.
- Рендер: markdown-it (MIT) и highlight.js в `Resources`, стили в духе GitHub, светлая и тёмная тема.
- Сырой HTML в Markdown выключен или чистится DOMPurify.

## Порядок и зависимости

```
0 Фундамент ──┬─ 1 Быстрые вещи
              ├─ 2 История / подсказки / закладки ─┐
              ├─ 3 Разрешения и PiP                ├─ 5 Профили ─ 6 Папки и группы ─ 7 Автоархив
              ├─ 4 Инкогнито ──────────────────────┘
              ├─ 8 Режим чтения, веб-приложения
              └─ 9 PDF и Markdown
```

Этапы 1, 3, 8 и 9 друг от друга не зависят, их можно делать параллельно. Этапы 2 → 4 → 5 → 6 → 7 идут строго по порядку: каждый следующий опирается на хранилище, профили или дерево из предыдущего.

Каждый этап — отдельная ветка и PR с обновлением README (сочетания клавиш) и `Documentation/AGENTS.md`, если меняется то, что видит агент.

## Проверка

**Юнит-тесты** (рядом с `URLRouterTests`):
- ранжирование истории;
- импорт закладок Chrome, Safari и HTML на файлах-образцах;
- лимит вложенности папок;
- правила попадания вкладки в группу;
- роспуск группы;
- стек закрытых вкладок;
- миграция старой сессии;
- выбор вкладок для автоархива.

**Вручную** на собранном `dist/Aircraft.app`, по списку для каждого этапа:
- инкогнито ничего не оставляет в `Application Support`;
- профили не видят cookie друг друга;
- PDF за логином открывается.

**Память.** До и после этапов 5, 6 и 9 замерять число живых WebView и память в Мониторе активности на одном и том же наборе из ~30 вкладок.
