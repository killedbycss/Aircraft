# Aircraft: идеи фич

Список фич, которые стоит добавить в Aircraft, собранный по Safari, Arc, Dia, Chrome, Zen и Vivaldi. Каждая фича оценена по двум осям: насколько она нужна пользователям и сколько стоит по памяти.

Главное правило про память: одна вкладка в WebKit — это отдельный процесс на 50–300 МБ. Дорого стоит всё, что держит живые WebView, а всё остальное почти бесплатно. Цифры ниже примерные.

## Что уже есть

Spotlight вместо адресной строки, усыпление вкладок, восстановление сессии, закреплённые вкладки, простой режим чтения на CSS, загрузки, блокировщики рекламы и трекеров, моды (история, сплит, темы, DevTools), Web Inspector, MCP для агентов.

## 1. Нужно всем, память почти не тратит

Начинать с этого.

| Фича | Откуда | Память | Почему дёшево |
|---|---|---|---|
| ⌘F, поиск на странице | Все браузеры | ~0 | `WKWebView.find(_:configuration:)`, работает на уже открытой странице |
| ⌘⇧T, вернуть закрытую вкладку + список недавно закрытых | Все браузеры | ~0 | Хранится только URL и история переходов; WebView создаётся заново |
| Масштаб ⌘+ / ⌘− / ⌘0 с запоминанием для сайта | Все браузеры | ~0 | Словарь «домен → масштаб» |
| ⌘⇧C, скопировать URL | Arc | 0 | — |
| Отключение звука и значок «играет» на вкладке | Chrome, Safari | ~0 | Флаг у существующего WebView (для mute нужен приватный API WebKit) |
| Окно разрешений: камера, микрофон, геолокация, уведомления | Все браузеры | ~0 | `requestMediaCapturePermissionFor` и список решений для каждого сайта |
| Вырезание `utm_*`, `fbclid`, `gclid` из ссылок | Safari | ~0 | Обработка URL перед переходом |
| Закладки с папками (закреплённые вкладки = закладки) | Arc, все | Единицы МБ | Данные на диске |
| Нативная история и подсказки в Spotlight: вкладки, история, закладки, поисковик | Все браузеры | 5–20 МБ | Только если хранить в SQLite с полнотекстовым поиском, а не держать всю историю в памяти |
| Импорт закладок и истории из Safari и Chrome | Все браузеры | 0 в работе | Разовая операция |
| Аварийное окно без истории | Все браузеры | Как обычное окно | `WKWebsiteDataStore.nonPersistent()` |

## 2. Нужно всем, но памяти стоит

Тут важно, как именно делать.

| Фича | Откуда | Память | Как не раздуть |
|---|---|---|---|
| Профили и Spaces: свои cookie, закреплённые вкладки и цвет | Arc, Zen, Safari | +30–60 МБ на каждый профиль | `WKWebsiteDataStore(forIdentifier:)` (macOS 14+). У каждого профиля свой сетевой процесс. Неактивный профиль выгружать; 2–3 профиля — это нормально |
| Picture-in-Picture, авто-PiP при уходе с вкладки | Arc, Safari | Держит вкладку живой | Пока видео в PiP, вкладку нельзя усыплять. Учесть в логике усыпления |
| Нормальный режим чтения на Readability.js | Safari | Пара МБ на время чтения | Подгружать скрипт только по нажатию |
| Перевод страницы через Apple Translation (macOS 15) | Safari, Chrome | 100–300 МБ, пока переводит | Модель грузится по требованию и потом выгружается |
| Блокировщики (уже есть) | Safari | 10–30 МБ | Правила компилируются один раз, огромные списки не нужны |

## 3. Полезные фичи без нагрузки

На них браузер и начинают любить.

- **Автоархив вкладок.** Вкладки, которые не трогали 12 часов, сутки или неделю, уходят в архив (Arc). Снижает расход памяти: это то же усыпление, только агрессивнее.
- **Командная строка в Spotlight.** Не только адреса, но и действия: «режим чтения», «отключить звук», «скопировать ссылку», «переместить вкладку в Space…».
- **Вложенные вкладки.** Вкладки, открытые со страницы, показываются деревом под ней (Zen, Vivaldi). По сути это поле «кто открыл» у вкладки.
- **Скрыть отвлекающее.** Кликаешь по элементу, он исчезает, и это запоминается для сайта (Safari 18). CSS-правила, как у блокировщика.
- **Папки вкладок** в боковой панели (Arc). Только интерфейс.

## 4. Полезные фичи, которые съедают память

Делать позже и с ограничениями.

| Фича | Откуда | Память | Риск |
|---|---|---|---|
| Peek / Glance: ⇧-клик открывает ссылку поверх страницы | Arc, Zen | +1 WebView (50–200 МБ) на время просмотра | Нормально, если уничтожать сразу после закрытия |
| Little Arc: ссылки из других приложений в маленьком окне | Arc | +1 окно и WebView | Нормально, если окно закрывается и не висит в фоне |
| Веб-панели сбоку (мессенджер, чат) | Vivaldi, Edge | +1 WebView на панель, постоянно | Дорого: панель живёт всегда. Нужен лимит или усыпление панелей |
| Счётчики непрочитанного на закреплённых вкладках | Arc | Держит вкладки живыми | Главная ловушка: счётчик работает, только пока вкладка не усыплена. Gmail, Telegram и Slack будут висеть по 200–400 МБ каждый. Включать отдельно для нужных вкладок |
| Сайт как приложение с иконкой в Dock | Safari | Отдельный процесс | Терпимо, по сути ещё одна вкладка |
| Сплит (уже есть) | Arc, Vivaldi | +1 WebView | Ок |

## 5. ИИ

Здесь у Aircraft фора: MCP для агентов уже есть.

| Фича | Откуда | Память | Комментарий |
|---|---|---|---|
| Чат со страницей, упоминание других вкладок через @ | Dia | ~0 | Через облачную модель: отправляется текст страницы, считается всё на сервере |
| Spotlight понимает вопросы и отвечает сам | Dia | ~0 | — |
| Навыки: сохранённые промпты через `/` | Dia | ~0 | «Перескажи», «сравни вкладки», «вытащи таблицу» |
| Объяснить, перевести, пересказать выделенное через контекстное меню | Dia, Edge | ~0 | Обёртка над чатом |
| Модель на устройстве через Apple Foundation Models (macOS 26) | — | Учитывается системой, а не браузером | Лучший вариант для приватности |
| Модель на устройстве через Ollama | — | 2–8 ГБ | Только как опция для тех, кто сам захочет |
| Поиск по истории по смыслу | Dia | 50–200 МБ индекса на диске, 20–50 МБ в работе | Индексировать в фоне на простое, а не при каждой загрузке страницы |
| Передать вкладку агенту одной кнопкой | — | ~0 сверху | MCP и подсветка рамкой уже есть |

## Что сложно из-за WebKit

- **Пароли.** Автозаполнение из «Паролей» или iCloud Keychain сторонний WKWebView-браузер просто так не получает, а расширения 1Password и Bitwarden не запустятся.
- **Passkeys.** Насколько известно, требуют от Apple специального разрешения для браузеров. Не проверено, нужно уточнить до того, как браться.
- **Расширения Chrome** полноценно работать не будут. Моды и встроенные функции тут правильный ответ.

## Порядок работ

1. **Сразу:** всё из раздела 1. Максимум пользы при нулевой цене по памяти. ⌘F, ⌘⇧T, масштаб, ⌘⇧C, вырезание трекинговых параметров и mute делаются за один-два вечера.
2. **Следом:** нативная история и подсказки в Spotlight, закладки, импорт из Safari и Chrome, разрешения сайтов.
3. **Потом:** профили и Spaces, автоархив, командная строка, папки. Автоархив заодно компенсирует расход на профили.
4. **С ограничителями:** Peek, Little Arc, PiP, перевод, режим чтения. Всё по требованию, с уничтожением WebView после использования.
5. **ИИ** поверх готового MCP: чат со страницей, навыки, модель на устройстве.
6. **Опционально, выключено по умолчанию:** веб-панели, счётчики непрочитанного, Ollama. С подписью в настройках, сколько они примерно стоят по памяти.

## Бюджет памяти

Стоит завести простой монитор: сколько живых WebView и сколько они занимают, со счётчиком в настройках или в окне разработчика. Тогда каждую новую фичу можно проверять по факту, а не на глаз.
